# 代码与性能维护说明

本轮保留主界面的布局、皮肤配置和用户数据格式，集中调整绘图基础设施与辅助窗口。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `surface.rs` | RGBA 数据、图片解码、缩放与缩放缓存 |
| `canvas.rs` | BGRA 软件画布、裁剪和透明混合，不访问窗口状态 |
| `file_icons.rs` | Windows Shell 图标提取及透明通道恢复 |
| `gdi_renderer.rs` | GDI 文字合成、字体句柄管理与截图导出，不访问应用状态 |
| `skin_assets.rs` | 皮肤与内置资源的组织和加载；保留原有导出入口 |
| `local_clock.rs` | Windows 当前时区与本地时间；日期格式仍交给 chrono |

## 性能约束

- `RgbaSurface` 克隆共享像素，修改通过写时复制隔离。不要绕过 `pixels_mut()` 修改数据，否则缩放缓存无法失效。
- 16×16 和 32×32 的缩放结果按图像共享，其他尺寸按需计算。仍使用 Lanczos3，不降低图标质量。
- 普通图像绘制一次计算裁剪范围，并分别处理透明、不透明、半透明像素；混合舍入保持兼容。
- GDI 字体按线程复用，缓存超过 16 项时在下一帧开始释放旧字体。释放前必须确保字体已经从 DC 中换出。
- 网站图标使用两个后台工作线程，相同待处理请求合并。网络操作不进入窗口线程。
- 同一批拖入生成图标后，统一保存一次完整快捷方式数据。
- 图片编码和缩放直接借用输入像素，避免额外复制完整输入缓冲区。

## 依赖与发布

保留现有六项直接依赖，关闭 chrono 的跨平台时区探测及 windows 的无用默认特性。当前锁文件包数从 79 减少到 58，不代表运行时少加载 21 个 DLL。图片格式支持保持不变。

发布版使用 thin LTO、单代码生成单元，并移除调试信息；不改变 panic 策略。

## 验证方式

在隔离数据目录执行构建、原生窗口回归和截图比较，避免修改真实 `user/` 数据：

```powershell
cargo test --offline --target-dir target/spacing-verify
cargo build --offline --release --target-dir target/spacing-verify
```

设置 `KSTART_CATEGORY_PREVIEW_DIR` 后，类别对话框测试还会执行原生窗口验证并输出截图；需要预先准备 `target/icon-verify` 隔离资源目录。设置 `KSTART_PERF=1` 可运行 `perf_tests` 中的可选微基准。

本轮同机 Debug 微基准示例：2000 次 256×256 图片克隆从约 168 ms 降至 0.054 ms；300 次重复 64×64 → 16×16 缩放从约 634 ms 降至 2.2 ms；1500 次透明图片绘制从约 108 ms 降至 53 ms。重复缩放包含缓存命中，绘制样本为透明图；这些数字仅表示对应操作，不能推导整机响应或常驻内存改善比例。

当前自动回归覆盖 33 项测试，包括像素混合一致性、写时复制和缓存失效、字体资源、时间兼容、间距、托盘菜单、靠边隐藏、透明度和批量拖入保存。主界面普通、选中和皮肤菜单三组截图与重构前基线逐像素比较。
