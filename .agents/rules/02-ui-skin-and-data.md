# UI、皮肤与用户数据规范

本文件定义皮肤配置、界面行为和持久化契约。窗口消息与资源安全见 [Win32 / GDI 安全规范](01-rust-win32-safety.md)。

## 1. 皮肤发现与加载

- `scan_skins` 枚举 `skin/` 中含 `Setup.ini` 的直接子目录，按目录名排序。发现皮肤后仍需通过配置和贴图加载检查。
- 作者说明读取 `Pre.txt`，兼容 UTF-8 与 GBK。缩略图优先读取 `<皮肤目录名>.gif`，其次读取 `Pre.gif`。
- 优先选择 `user/config.ini` 中 `Skin` 指定且存在的皮肤。配置缺失、为空或找不到指定名称时，选择排序后的第一款皮肤。

## 2. `Setup.ini` 配置契约

- 新增配置使用语义化字段，如 `Window*`、`CornerMask*`、`Menu*Color`、`TitleBtn*`、`CategoryTab*` 和 `SearchBox*`。保留 `SkinConfig::load_from_ini` 对既有旧字段的回退读取，语义化字段优先。
- `CoordExpr` 中的整数是相对窗口左上角的绝对像素，按钮可用负坐标移出可视区。`R<N>` 解析为窗口宽度减 `N`，`B<N>` 解析为窗口高度减 `N`。
- 八切片窗口按边与角分别加载。色键透明仅在 `CornerMask*` 指定的对应角区内计算，交由主窗体区域裁剪。
- 贴图清单、字段速查和皮肤验收见[皮肤编写手册](../skills/kstart-skin-authoring/SKILL.md)。

## 3. 弹出菜单与对话框

### 弹出菜单

- 所有菜单使用独立的 Win32 顶层弹出窗口（`KStartPopupMenuClass`），并共用当前皮肤的菜单样式。以触发位置所在显示器的工作区定位，允许菜单显示在主窗体范围之外。
- 搜索菜单向搜索按钮右侧展开，右侧空间不足时向左展开。
- 左下角主菜单仅在明确命中 `ToolButtonKind::MainMenu` 时打开。列表外其他空白位置的右键操作可关闭已打开的菜单。
- 离线合成菜单预览时，裁剪菜单下方的文字像素并保留原文字布局，避免被遮挡的文字穿透菜单或使居中文本偏移。

### 对话框

- 管理对话框、关于窗口和搜索结果窗口使用独立顶层窗口并居中显示。原生管理对话框使用 `KStartNativeDialogClass`，搜索结果和自绘对话框使用 `KStartModalDialogClass`。
- 右键新建快捷方式先打开编辑窗口，用户确认后才写入数据。文件、目录和图标选择应遵守[窗口消息重入规则](01-rust-win32-safety.md)。

## 4. 控件与搜索行为

- 四边与四角缩放命中区使用对应的系统缩放光标。按钮、菜单项、标签、分组条、链接和快捷方式用手形光标，文本输入区用文本光标，其余空白及拖拽区用箭头光标。
- 左上角预览区固定使用默认文件夹图标并居中展示。悬停不切换底图或文件夹图标。
- 类别标题由皮肤配置决定。皮肤自带搜索框底图时，使用 `SearchBoxUseSkinBackground` 保留该底图。
- 搜索框编辑期间保持主列表布局和内容，回车时按选中的模式提交。搜索结果窗口依次显示关键词、模糊选项和搜索按钮，结果数与双行列表，以及范围和取消。结果行展示图标、名称和目标路径。初始选中首项，有结果时用方向键选择，回车执行。

## 5. 用户数据契约

| 文件 | 格式与约定 |
| --- | --- |
| `user/config.ini` | 统一保存主窗口、高级设置、字体、间距、使用计数、热键和口令验证值。依次使用 `[Config]`、`[Advanced]`、`[Fonts]`、`[Spacing]`、`[Usage]`、`[Hotkeys]`、`[Verification]`。`[Hotkeys]` 以组合键为键，每条记录保存启用状态、备注和结构化目标。目标可以引用快捷方式 ID、保存独立快捷方式目标，或保存当前 Windows 用户加密的输出文本。兼容旧版 ID 和 `/AH/`、`/Search/` 等单值。 |
| `user/data.json` | UTF-8 JSON。顶层包含 `categories`、`columns`、`shortcuts`。栏目以 `category_id` 关联类别，快捷方式以 `category_id` 和 `column_id` 关联类别和栏目。目标类型 `target_kind` 为 `file`、`folder`、`system`、`web` 或 `launcher`。文件和目录按 `path_mode` 区分相对和绝对路径，起始目录使用 `work_dir_mode`。相对路径以 KStart 数据根目录为基准。 |
| `user/plan.json` | 独立保存计划任务、执行类型、日期时间、启用状态、提醒、批处理步骤与触发记录。不得写入 `data.json`；支持备份和恢复。任务执行不得在 `APP_STATE` 借用中打开窗口或调用启动操作，批处理延时不得阻塞消息循环。 |
| 图标来源 | 拖入文件、文件夹时直接读取对象的 Shell 图标；`.lnk` 读取目标程序的图标。`icon_key` 保存图标来源路径。手动选择图标也只引用来源文件，不复制图标。 |

高级设置按页编辑草稿，确定后应用，取消丢弃表单更改。重置只恢复当前页。备份、恢复、创建系统快捷方式和修改口令由各自的按钮单独发起。

- 每个配置项均有默认值。配置文件缺失时，在内存中使用默认值，保存时一次写入完整配置。对应节缺失时，可读取旧版 `advanced-settings.json`、`hotkey.ini` 和 `*.credential`，后续保存统一写入 `config.ini`。
- 不创建 `user/icons/` 或 `user/icon-cache/`，不将文件或网页图标缓存到磁盘；图标像素仅用于内存中的界面显示。
- `[Verification]` 只存储加盐后的口令验证值。常规数据备份省略验证值，恢复备份时保留当前验证值。

写入数据应复用既有模型及持久化路径，保持旧数据的读取兼容性。验证中涉及设置、缩放落盘或数据修改时，应使用隔离的用户目录。验证步骤见[构建与验证手册](../skills/kstart-build-and-verify/SKILL.md)。
